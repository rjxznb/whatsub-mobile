# LLM 权益收口与 Pro Token 加量包设计

**日期：** 2026-08-21  
**涉及仓库：** `whatsub-license`、`whatsub-mobile`、桌面端 `whatsub/client`、`whatsub-website`  
**状态：** 已确认设计，待实施计划

## 1. 背景与目标

当前免费用户在托管 LLM 的一次性体验额度耗尽后，仍可在手机端或桌面端配置自己的 OpenAI-compatible API Key（BYOK），从而长期使用主要 AI 功能。这削弱了 Pro 订阅和 ¥59.9 永久授权的付费价值，也导致各端对同一账号的能力判断不一致。

本次调整要完成两件事：

1. 收紧 BYOK：只有购买了 ¥59.9 永久授权的邮箱才能在手机端和桌面端使用 BYOK。
2. 为有效 Pro 用户增加 Token 加量包：月度 5M Token 用完后可以购买永不过期的额外额度，并从断点继续任务。

本设计不改变免费用户现有的一次性托管体验额度，也不取消 Pro 每月 5M Token。永久授权仍统一在网站购买；桌面端通过序列号激活，手机端通过登录邮箱与后端购买记录关联。

## 2. 产品原则

- 免费体验用于证明价值，不提供可无限使用的 BYOK 逃生通道。
- ¥59.9 永久授权是 BYOK 权益，不包含 whatSub 托管模型成本。
- Pro 订阅默认使用托管 LLM，不要求用户配置第三方 Key。
- 同时拥有永久授权和 Pro 的用户同时拥有托管与 BYOK 两种能力。
- 加量包只能由有效 Pro 购买和使用，不能替代订阅。
- 充值 Token 永不过期；Pro 到期时冻结，重新订阅后恢复。
- 已保存的 API Key 不因权益变化而删除，只在无 BYOK 权限时禁止展示和调用。

## 3. 权限矩阵

| 账号状态 | 托管 LLM | BYOK | Token 加量包 |
|---|---|---|---|
| 免费 / 体验 | 允许，受一次性体验额度限制 | 不允许 | 不允许 |
| 仅 ¥59.9 永久授权 | 不允许 | 允许 | 不允许 |
| 仅 Pro | 允许，5M/月 + 充值余额 | 不允许 | 允许 |
| 永久授权 + Pro | 允许，5M/月 + 充值余额 | 允许 | 允许 |

后端返回的是“是否允许使用某种模式”，不是“当前是否还有额度”。例如免费用户的 `managedRelay` 能力为 `true`，但体验额度可能已经为零；额度状态由 quota 响应表达。

`/api/license/auth/me` 增加服务端权威字段：

```json
{
  "llmEntitlements": {
    "tier": "free",
    "managedRelay": true,
    "byok": false,
    "tokenTopups": false
  }
}
```

`tier` 取值为 `free | buyout | pro | buyout_pro`。三个布尔能力用于客户端展示和调用前拦截；客户端不得自行用零散字段重新推导另一套规则。

## 4. 权益来源与跨端关联

### 4.1 永久授权

- 永久授权继续统一通过网站以 ¥59.9 购买。
- 购买时必须绑定标准化后的邮箱；后端 `licenses.email` 是手机端识别 BYOK 权益的来源。
- 桌面端仍使用序列号进行设备激活，同时登录购买邮箱以获得跨端账号能力。
- iOS 不要求输入序列号，只读取当前登录邮箱的 `llmEntitlements.byok`。
- iOS 内不展示网站购买链接、支付宝入口或“去网站购买”的引导，避免违反 App Store 外部支付引导规则。

### 4.2 Pro 订阅

- `hasActiveSubscription` 继续合并 Apple StoreKit 与网站/支付宝订阅。
- Pro 有效时开放托管 LLM 和 Token 加量包。
- 永久授权与 Pro 可共存；共存时不互相覆盖。

### 4.3 刷新时机

客户端在以下时机刷新权益：

- 登录完成；
- App 回到前台；
- StoreKit、支付宝订阅或加量包购买完成；
- 用户主动下拉刷新账号页；
- 托管接口返回与本地能力缓存不一致的 401/403。

权益查询失败时保留最近一次已确认结果和已有 Key；从未确认过 BYOK 权益的账号默认不开放 BYOK。退出账号时必须清除该账号的能力缓存，不能沿用上一个账号的权限。

## 5. 客户端模式收口

手机端和桌面端都必须在两层执行权限：

1. **入口层：** 只展示账号允许的模式、按钮和设置字段。
2. **调用层：** 在创建 LLM provider 或发起请求之前再次检查能力，防止深层入口、旧导航状态或持久化配置绕过 UI。

升级后的模式迁移规则：

- 免费或仅 Pro：强制使用托管模式，隐藏 BYOK 字段。
- 仅永久授权：强制使用 BYOK；未配置 Key 时引导填写。
- 永久授权 + Pro：保留用户上次选择的托管/BYOK 模式。
- 无权使用 BYOK 时，Keychain 或桌面本地安全存储中的 Key 原样保留，但任何调用都不得读取并发送它。

所有旧文案中“切换自己的 API”“配置 Key 后继续”等建议都必须改为按能力动态出现。免费用户和仅 Pro 用户不能再看到 BYOK 作为恢复方案。

## 6. 免费额度耗尽交互

### 6.1 开始任务前耗尽

当免费用户再次发起视频解析、视频概览、深度释义、角色扮演等托管调用并收到 `free_used_up` 时，显示上下文订阅页：

> 免费 AI 体验额度已用完  
> 已下载的英文字幕和当前解析进度都会保留。订阅 Pro 后可继续解析，无需重新下载字幕。

操作：

- 主按钮：`订阅 Pro，继续解析`
- 次按钮：`暂时不解析`

不显示 BYOK、LLM 设置或自己的 API Key。

### 6.2 后台任务中途耗尽

- 任务进入 `pausedQuota`，不是 `failed`。
- 已完成字幕、翻译、重点词和持久化 checkpoint 全部保留。
- Library 视频页和导入队列都显示“订阅后继续”。
- 订阅成功后刷新权益并从 checkpoint 自动恢复，不重新下载、转录或重做已持久化字幕。
- 用户关闭页面或 App 不会丢失恢复入口。

### 6.3 通用 AI 功能

非视频任务收到 `free_used_up` 时统一映射为订阅 upsell，不再映射到 LLM 设置。所有入口复用同一错误分类和 CTA，避免每个页面各写一套判断。

## 7. Pro 月度额度耗尽交互

- 使用达到月度额度的 80% 时显示轻量提醒，不中断当前任务。
- 月度 5M 耗尽且充值余额为零时暂停新请求，保留当前任务 checkpoint。
- 仅 Pro 用户看到三档加量包和下次月度重置时间。
- 永久授权 + Pro 用户同时看到“购买 Token”和“切换到 BYOK”。
- 仅 Pro 用户不显示 BYOK。
- 月度额度在重置时间恢复后，暂停任务可以直接继续。

额度界面统一显示：

- 本月订阅额度：已用 / 5M；
- 充值余额；
- 下次重置时间；
- 当前请求优先消耗月度额度还是充值余额。

## 8. Token 加量包商品

| 商品 | Token | 中国区价格 | 商品 ID |
|---|---:|---:|---|
| 小额加量包 | 1M | ¥10 | `whatsub_token_1m` |
| 标准加量包 | 5M | ¥45 | `whatsub_token_5m` |
| 重度加量包 | 15M | ¥125 | `whatsub_token_15m` |

- iOS 使用 StoreKit 消耗型内购，并显示 StoreKit 返回的本地化价格。
- 网站/桌面端通过支付宝购买相同额度。
- 两种渠道都绑定邮箱并写入同一个后端余额账本。
- 加量包只能在有效 Pro 状态下发起购买。
- 如果支付完成时 Pro 恰好到期，合法交易仍必须入账，避免扣款不发货；余额随后处于冻结状态。
- 产品目录由后端配置并返回，客户端不把金额作为记账依据。后续价格或赠送额度调整只影响新订单，不迁移已有余额。

## 9. Token 账本与扣费顺序

### 9.1 数据模型

新增三类持久化记录：

1. `llm_token_wallets`：每邮箱的可用充值余额、已预留额度和更新时间。
2. `llm_token_transactions`：不可变审计账本，记录充值、结算、退款调整和人工调整；`(source, external_transaction_id)` 唯一。
3. `llm_token_reservations`：请求级预留，记录月度额度和充值余额各自预留多少、最终结算多少及过期时间。

金额只用于订单审计；LLM 消耗统一以整数 Token 记账。

### 9.2 扣费顺序

1. Pro 当月 5M；
2. 充值余额；
3. 两者都不足时返回 quota 错误并暂停任务。

输入和输出 Token 都按模型返回的实际 usage 计入当前统一额度口径。充值余额跨月累计且永不过期；Pro 失效后只冻结消费，不清零。

### 9.3 并发预留与结算

- 请求进入模型队列前，在数据库事务内按邮箱加锁。
- 根据估算输入和服务端允许的最大输出创建额度预留。
- 月度剩余额度优先承担预留，不足部分从充值钱包预留。
- 可用额度不足时不调用上游模型。
- 请求结束后用实际 usage 结算，释放未使用的预留。
- 请求取消、上游失败或 admission 拒绝时释放对应预留。
- 异常断流且拿不到完整 usage 时沿用现有保守估算规则，不能让主动断开成为逃费手段。
- 定时任务回收超时且无活跃请求的孤儿预留。

该模型保证手机、桌面和多个后台任务并发时不会重复消费同一余额，也不会把钱包扣成负数。

## 10. 支付入账与幂等

### 10.1 Apple

- 新增三个 StoreKit consumable product。
- 客户端购买后把签名交易发送至后端验证。
- 后端验证 bundle、product ID、transaction ID 和签名环境。
- 以 Apple transaction ID 作为幂等键；未完成交易重新投递、客户端重试或服务端通知只入账一次。Consumable 不提供传统“恢复购买”入口。

### 10.2 支付宝

- 网站创建明确的 Token 商品订单，后端保存下单时的商品快照。
- 支付回调与主动查询共用原子 claim，避免双重入账。
- 以支付宝订单号/whatSub 订单号的唯一约束保证幂等。

### 10.3 退款与撤销

- 未消费余额可通过审计交易进行冲正，但余额不能自动扣成负数。
- 已消费加量包的退款进入人工审核，不直接破坏已完成的 usage 账本。
- 所有人工调整必须记录操作者、原因和关联交易。

## 11. 各端界面

### 11.1 iOS

- 免费：LLM 设置只显示托管体验与剩余额度；隐藏模式开关和 BYOK。
- 仅买断：只显示 BYOK 配置。
- 仅 Pro：只显示托管额度；达到阈值后显示 StoreKit 加量入口。
- 买断 + Pro：显示托管/BYOK 切换，并可购买加量包。
- iOS 不展示网站充值或永久授权购买链接。
- 购买完成后刷新 quota，并自动恢复触发购买的暂停任务。

### 11.2 桌面端

- 免费体验耗尽：引导订阅 Pro，不再开放 BYOK。
- 仅买断：显示 BYOK 设置，不显示托管充值。
- 仅 Pro：额度耗尽后通过网站/支付宝购买加量包。
- 买断 + Pro：同时提供充值与切换 BYOK。
- 支付窗口完成后轮询订单状态，余额到账即恢复后台解析。

### 11.3 网站

- 只有已登录且 Pro 有效的账号可以创建 Token 订单。
- 展示三档商品、当前充值余额和交易记录。
- 非 Pro 点击购买时先进入 Pro 订阅流程。
- 订单页明确说明：充值 Token 永不过期，但只能在 Pro 有效期间使用。

## 12. 错误契约

后端保留现有稳定错误码，并补充充值场景：

- `free_used_up`：免费一次性体验耗尽，订阅 CTA。
- `quota_exceeded`：Pro 月度额度与充值余额均不足。
- `license_blocked`：仅买断账号尝试托管，应切换 BYOK 或订阅 Pro。
- `byok_not_entitled`：官方客户端在调用前使用的统一本地错误；若新增服务端 BYOK 相关接口，同样使用该码。
- `topup_requires_pro`：非 Pro 尝试创建加量订单。
- `topup_product_invalid`：未知或未启用商品。
- `topup_transaction_conflict`：同一外部交易与不同账号或商品冲突。

错误响应应带稳定 code 和中文 message；客户端按 code 决定 CTA，不解析 message 文本。

## 13. 旧版本与安全边界

BYOK 是设备直接访问用户选择的第三方模型服务，不经过 whatSub 后端。因此后端无法远程阻止仍安装旧版、关闭自动更新或自行修改客户端的用户继续使用旧版 BYOK。

本次保证的是：

- 新版官方客户端没有免费 BYOK 入口；
- 所有新版官方调用路径执行能力检查；
- 服务端功能和云端额度继续独立鉴权；
- 新功能可以要求最低客户端版本。

不把“绝对阻止篡改客户端”作为本期目标。旧版本迁移通过正常更新、桌面自动更新提示和后续服务端最低版本策略逐步完成。

## 14. 埋点与隐私

记录以下不含 API Key 或字幕正文的产品事件：

- 免费额度耗尽页曝光；
- 订阅按钮点击及结果；
- Pro 80% 提醒曝光；
- 加量包曝光、档位选择、购买成功/失败；
- 购买后任务自动恢复成功/失败；
- 买断 + Pro 用户选择充值或 BYOK。

这些数据用于判断免费体验是否促成订阅、加量包是否有真实需求，以及三档价格是否合理。

## 15. 测试策略

### 15.1 后端

- 四种账号状态的权限矩阵。
- 邮箱大小写标准化及跨端一致性。
- 月度额度优先、充值余额其次。
- Pro 到期冻结、重新订阅解冻。
- Apple/支付宝重复回调只入账一次。
- 合法支付在订阅到期竞态下仍入账。
- 多设备并发预留不超卖、不产生负余额。
- 请求成功、失败、取消、断流的结算与释放。
- 孤儿预留回收。
- 未知商品、伪造交易、跨账号交易冲突拒绝。

### 15.2 iOS

- 四种账号对应的 LLM 设置布局与可调用模式。
- 免费/Pro 已保存 Key 升级后保留但不可读取调用。
- 免费额度耗尽后订阅并恢复原任务。
- Pro 耗尽后购买三档商品并恢复原任务。
- 买断 + Pro 可选择充值或 BYOK。
- 退出账号后不继承 BYOK 权限。
- StoreKit pending、cancelled、重复回调及未完成交易重新投递。
- 无外部网站购买引导。

### 15.3 桌面端与网站

- 序列号激活和邮箱权益的一致性。
- 免费用户无法从设置、深层链接或持久化配置进入 BYOK。
- 支付宝订单支付、重复通知、主动查询和自动恢复。
- 后台任务在 quota 暂停后保留 checkpoint。
- 买断 + Pro 的双模式切换。

## 16. 上线顺序

1. 后端权益字段、钱包、账本、预留和支付验证；默认关闭加量商品。
2. 网站支付宝商品与管理/审计界面。
3. App Store Connect 创建三个消耗型商品并完成沙盒配置。
4. 桌面端新版发布并验证权限迁移。
5. iOS TestFlight 验证四种账号和三档购买。
6. 观察内部账号账本与自动恢复结果。
7. 服务端开启商品目录，最后开放正式购买入口。

后端必须先于客户端上线，并保持旧响应字段兼容。客户端只有在商品目录和 StoreKit 商品都可用时才显示购买入口，避免用户看到无法完成的支付按钮。

## 17. 非目标

- 不改变 Pro 月费 ¥38、月度 5M Token 或其他 Pro 权益。
- 不允许非 Pro 单独购买 Token 来替代订阅。
- 不把充值 Token 兑换为现金、转赠其他邮箱或跨账号合并。
- 不删除用户已有 BYOK Key。
- 不在 iOS 内引导网站购买永久授权或支付宝充值。
- 不尝试从后端绝对封禁旧版或篡改客户端的本地 BYOK 请求。
