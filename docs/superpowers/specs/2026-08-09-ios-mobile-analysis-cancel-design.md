# iOS Library 后台解析停止与继续设计

日期：2026-08-09

## 目标

让用户在 Library 视频详情页查看渐进式 AI 解析进度时，可以主动停止服务器后台解析。停止后保留英文字幕以及已经完成并持久化的翻译批次，未完成部分不再继续消耗服务器资源；用户之后可以从未完成批次继续解析。

## 现状

- 后端已经提供 `POST /api/library/mobile-analysis/jobs/:id/cancel` 和 `/resume`。
- 取消会把任务设为 `cancelled`、释放租约，并由 worker 的取消监听终止正在进行的上游请求；已经提交完成的批次不会删除，正在生成但尚未提交的批次会被丢弃。
- iOS Import 提交页和“我的 → 导入队列”已经能够取消任务。
- Library 视频详情页能够显示排队、解析、暂停、失败和继续状态，但解析进行中没有停止入口。

## 交互设计

### 进行中

当状态为 `queued` 或 `running` 时，在 Library 详情页 AI 进度横幅右侧显示紧凑的“停止”按钮。按钮与现有“继续 AI 解析”使用同一操作区域，不增加新的大卡片或工具栏入口。

点击“停止”后弹出确认框：

- 标题：`停止 AI 解析？`
- 说明：`已完成的翻译会保留，未完成部分将停止解析，之后可以继续。`
- 取消按钮：`继续解析`
- 破坏性按钮：`停止解析`

用户确认后，按钮显示 `正在停止…` 并禁用重复操作。视频播放和已经出现的字幕不受影响。

### 已停止

取消成功后：

- 已经有完成字幕时，横幅显示 `部分解析 · 已停止`；尚无完成字幕时显示 `仅英文 · 已停止`。两者都映射到同一个后端 `cancelled` 状态，只根据 `completedCues` 选择准确文案。
- 已完成批次继续覆盖到英文字幕上，未完成字幕保持英文并显示等待 AI 的现有占位样式。
- 横幅右侧显示现有的 `继续 AI 解析`。
- 继续后复用 `/resume`，后端仅处理未完成批次，不从头解析。

## 客户端结构

`LibraryDetailView` 只负责按钮、确认框和加载态。`LibraryDetailViewModel` 新增停止动作状态和 `cancelManagedAnalysis(token:)`：

1. 读取当前 `managedProgress.jobID`；
2. 调用现有 `ManagedAnalysisClientProtocol.cancel`；
3. 用响应更新 `ManagedAnalysisProgressState`；
4. 停止进度轮询并保留 `ProgressiveAnalysisOverlay`；
5. 失败时保持原任务状态并设置可重试的中文错误。

不新增后端接口、不删除 provisional Library 条目、不清空已经合并的字幕，也不改变 Import 页原有取消行为。

## 并发与竞态

- 如果任务在确认期间已经完成，后端会返回 `invalid_state`；客户端随后刷新一次任务/结果状态，优先展示完成结果，不误报“停止失败”。
- 如果取消与一个批次提交同时发生，后端事务和租约状态决定最终结果；客户端以取消响应及下一次结果刷新为准。
- 页面退出会停止本地轮询，但不会自动取消服务器任务；只有用户确认“停止解析”才发送取消请求。
- 停止请求进行中禁止再次停止或继续，避免相反操作并发。

## 错误处理

- 网络或服务器失败：保持原进度状态，横幅显示 `暂时无法停止解析，请稍后重试`。
- 登录过期：沿用现有会话错误处理，不把任务误标为已停止。
- 取消成功后本地轮询任务立即结束；重新进入页面时通过现有 job discovery 恢复 `cancelled` 状态及已完成批次。

## 测试

- ViewModel：运行中取消成功，状态变为 `cancelled`，轮询停止，已合并字幕不回退。
- ViewModel：取消失败时保留原状态并显示错误。
- ViewModel：取消与完成竞态时能刷新并显示最终完成结果。
- Presentation：`queued/running` 可以停止，`cancelled` 可以继续，其他终态不显示停止。
- 现有渐进式合并、继续解析和最终结果同步测试保持通过。

## 发布

该功能需要新的 iOS binary，因此实现验证后发布一版 TestFlight。后端取消/继续能力已经上线，此功能本身不要求新增后端部署；后台解析截断自动重试修复仍按其独立后端发布流程部署。
