# 视频学习导览与重点词深度解读布局优化设计

**日期：** 2026-08-14
**范围：** iOS `Library` 视频详情页，不改后端接口、缓存格式或 AI 返回结构。

## 背景

当前界面存在三个直接影响使用的问题：

1. 视频学习导览卡片位于固定 `VStack` 中，展开后没有可滚动容器。内容超过剩余屏幕高度时，后半部分无法访问，并会挤压字幕区域。
2. 重点词释义 sheet 默认使用固定 `340pt` 高度。导航栏、发音、简要释义、收藏按钮共同占用空间后，“深度解读”按钮只能露出一部分。
3. 深度解读结果按“标题 + 连续正文”平铺，多个语义部分缺少视觉分组；自然替换表达虽然是数组，界面却合并成多行纯文本，不容易逐条阅读。

## 目标

- 展开视频学习导览后，全部内容都能通过滚动访问。
- 导览卡片不无限增长，不长期挤掉字幕列表。
- 重点词弹窗首次出现时完整展示主要内容和两个操作入口。
- 用户发起深度解读后，弹窗自动提供足够的阅读空间。
- 深度解读各部分层次清楚，自然替换表达可以逐条扫读。
- 保持现有生成、缓存、收藏和错误重试逻辑不变。

## 非目标

- 不修改 DeepGloss 或 LearningGuide 的后端 JSON schema。
- 不重新生成已有视频总览或重点词解释。
- 不改变字幕列表、视频播放器或单词收藏业务流程。
- 不让整个视频详情页变成一个统一外层 `ScrollView`，避免与字幕列表发生嵌套滚动冲突。

## 交互设计

### 1. 可滚动的视频学习导览

折叠状态保持现状：显示结论、CEFR 和一行概览。

展开状态中：

- 折叠标题行保持在卡片顶部，不随正文滚走。
- 正文放入独立的纵向 `ScrollView`。
- 正文设置一个与设备可用空间相适应的最大高度；内容较短时按内容自然高度显示，内容较长时才启用内部滚动。
- 保留现有“重点片段”点击后跳回字幕并定位播放的行为。
- 显示滚动指示器，让用户能感知后面仍有内容。

这种方式只在导览卡片内部产生滚动，不改变字幕列表已有的滚动容器。

### 2. 重点词释义 sheet 高度

- 默认 detent 从固定 `340pt` 改为屏幕高度约 `65%` 的 fraction detent。
- 同时保留 `.large` detent，用户仍可手动上拉全屏。
- 点击“深度解读”或“重试深度解读”时，先把当前 detent 切换到 `.large`，再发起请求。
- sheet 内部继续使用现有 `ScrollView`，小屏设备和超长结果仍能完整访问。

默认中等高度保留视频上下文，又能完整露出发音、释义、收藏和深度解读按钮。

### 3. 深度解读结果样式

每个可见 section 使用独立的信息卡片：

- 左侧使用小型 SF Symbol 或强调色圆点作为视觉锚点。
- 右侧显示 section 标题和内容。
- 卡片使用轻微底色、圆角和统一内边距，不使用过重边框。
- 普通说明保持自然段展示。
- “自然替换表达”将原始数组逐条显示为项目符号列表，不再用换行字符串伪装列表。
- “使用提醒”使用暖色图标或弱警示底色，但正文仍保持可读，不做强烈错误提示。

建议的图标映射：

- 此处含义：`text.quote`
- 语气与言外之意：`bubble.left.and.text.bubble.right`
- 俚语 / 习语：`quote.bubble`
- 文化语境：`globe.asia.australia`
- 自然替换表达：`list.bullet`
- 使用提醒：`exclamationmark.triangle`

## 数据与组件边界

- `DeepGlossResult` 保持不变。
- `DeepGlossPresentation.visibleSections` 继续负责过滤空 section。
- `DeepGlossSection` 增加适合展示的逐行内容访问方式，或由 View 根据 `.naturalAlternatives` 的 section kind 将 `content` 拆分；优先选择可单元测试、不会把展示规则散落在 View 中的实现。
- `GlossSheet` 只负责 detent 状态和 section card 渲染。
- `VideoLearningGuideCard` 自己拥有展开正文的滚动边界，不把滚动责任交给 `LibraryDetailView`。

## 无障碍与适配

- 卡片内容支持 Dynamic Type，正文不使用固定行高或截断。
- 项目符号列表保持逐条可读的 VoiceOver 顺序。
- sheet 的 fraction detent 与 `.large` 在 iPhone 小屏和大屏上按比例适配。
- iPad 继续表现为系统 sheet；内部滚动保证内容不依赖具体弹窗像素高度。
- 图标只承担辅助分组作用，section 标题仍提供完整语义。

## 测试策略

先补失败测试，再实现布局：

1. `GlossSheetLayoutTests`
   - 默认 detent 为约 65% 的 fraction，而不是固定 `340pt`。
   - 点击深度解读的路径仍会切换到 `.large`。
   - sheet 同时提供默认 detent 与 `.large`。
2. `DeepGlossTests`
   - 自然替换表达保留独立条目顺序，可供项目符号列表渲染。
   - 空 section 继续被过滤。
   - 每个 section kind 获得稳定的展示元数据。
3. `VideoLearningGuidePresentationTests` 或新增布局测试
   - 展开内容位于 `ScrollView` 中。
   - 滚动只包裹展开正文，折叠标题位于其外部。
   - 重点片段选择行为保持不变。
4. 运行完整 iOS 单元测试与 simulator build，确认没有布局相关编译回归。

## 风险与控制

- **嵌套滚动手势冲突：** 只给导览卡片正文加滚动，不包裹整个详情页；字幕列表保持原结构。
- **导览正文过矮：** 最大高度应允许看到至少两个完整 section，并通过设备可用高度设置合理上下限。
- **深度解读卡片过度占空间：** 使用紧凑间距和弱背景，不为每段增加大标题或装饰性留白。
- **旧缓存兼容：** 不改 Codable 模型和持久化格式，已有结果可直接使用新样式展示。
