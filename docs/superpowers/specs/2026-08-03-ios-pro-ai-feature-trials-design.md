# iOS Pro AI 功能与一次性体验设计

**日期：** 2026-08-03
**状态：** 产品方向已确认，等待实施计划
**涉及仓库：** `whatsub-mobile`、`whatsub-license`

## 1. 背景与问题

当前 iOS 免费版已经可以形成完整的独立使用闭环。免费用户可以登录、播放云端视频、查看字幕、维护少量个人语料、使用单词卡，并直接进入对话陪练、视频角色扮演、实景口语和拍照 AI。用户还可以关闭 whatSub 托管 LLM，填写自己的 API Key（BYOK），从而绕过托管 token 配额，长期使用这些高价值 AI 功能。

现有 Pro 的主要差异集中在公共语料库、云端容量和托管 token 配额。它们对只维护少量视频、愿意使用自己 API Key 的手机端用户吸引力不足，因此出现“用户只用手机端也可以长期不付费”的商业漏洞。

本设计将“功能权益”和“AI 调用费用”分开：

- Pro 决定用户能否持续使用高价值 AI 功能。
- 托管 LLM 或 BYOK 只决定 AI 请求由谁承担 token 成本。
- 免费用户仍然可以完整体验每项核心 AI 功能一次，而不是安装后立即遇到硬付费墙。

## 2. 目标

1. 为手机端建立清晰、可感知的 Pro 核心价值。
2. 保留足够的免费基础功能用于拉新和建立学习习惯。
3. 每个高价值 AI 功能提供一次完整体验，让用户先看到效果再决定订阅。
4. BYOK 不再绕过功能权益，但继续作为 Pro 用户的模型与成本选择。
5. 免费体验记录按账号跨设备同步，重装 App 或更换设备不会重置。
6. 网络失败、模型失败和无有效结果的尝试不消耗免费体验。
7. 复用现有订阅、身份和 StoreKit 体系，不引入新的商品类型。

## 3. 非目标

- 不恢复首次启动全屏硬付费墙。
- 不限制字幕播放、基础收藏、单词卡或现有免费云同步额度。
- 不新增点数包、按次购买或第二套会员等级。
- 不取消 BYOK，也不把用户自己的 API Key 上传到 whatSub 服务端。
- 不改变现有 Pro 月度托管 token 配额计算方式。
- 不对单次免费会话设置固定轮数或强制时长上限。

## 4. 方案比较

### 方案 A：仅在 iOS 本地记录体验次数

实现最简单，服务端无需改动，但卸载 App、清除数据或换设备即可重置，不适合作为收费权益的权威来源。

### 方案 B：统一免费体验积分

给免费账号一组积分，所有 AI 功能共同扣减。它较灵活，但用户难以理解“某个功能还剩多少”，产品文案和异常补偿也会变复杂。

### 方案 C：服务端按功能记录一次性体验（采用）

服务端为四项功能分别记录体验状态。规则易解释、跨设备一致、可独立核销，也最适合当前“每项免费完整体验一次”的产品决定。

## 5. 权益边界

### 5.1 Pro 核心 AI 功能

以下四项功能改为 Pro 权益：

| 功能键 | 用户界面 | 免费权益 | Pro 权益 |
| --- | --- | --- | --- |
| `quick_chat` | 对话陪练 | 一场完整体验 | 持续使用 |
| `video_roleplay` | 视频角色扮演 | 一场完整体验 | 持续使用 |
| `live_scene` | 实景口语 | 一次完整流程 | 持续使用 |
| `photo_ai` | 拍照翻译/拍照 AI 分析 | 成功分析一张图片 | 持续使用 |

“一次”按一次任务或一次会话计算，不按 LLM 请求次数计算。对话陪练不强制限制为 5 轮，也不禁止用户选择现有的无限轮模式；一次会话从进入体验开始，直到用户正常结束或离开该会话。

### 5.2 继续免费的功能

- 登录和账号同步。
- Library 浏览、视频播放、双语字幕和字幕定位。
- 基础收藏和个人语料管理。
- 单词卡及其他纯本地练习。
- 当前免费云同步额度：3 个视频、单视频 100 MB / 20 分钟。
- 当前免费个人语料额度：50 条。
- 轻量的一次性释义、翻译或语料补全可继续使用 BYOK；它们不属于本次四项 Pro 会话功能。
- 现有公共语料库 Pro 权限和 Pro 容量扩容保持不变。

### 5.3 BYOK 规则

功能权益检查发生在选择 AI 传输方式之前：

1. iOS 先向 whatSub 服务端确认该功能可用。
2. 获得权限后，再根据 `LlmSettings.useManagedRelay` 决定走托管 LLM 还是 BYOK。
3. BYOK 的 API Key 仍只保存在用户设备 Keychain 中，不发送给 whatSub。
4. 免费体验已经用完时，即使 BYOK 配置完整，也必须订阅 Pro 才能再次进入四项核心功能。

## 6. 一次体验的生命周期

每项功能有三个服务端状态：

- `available`：该账号尚未体验。
- `in_progress`：已经开始本项免费体验，但尚未获得足以核销的有效结果。
- `consumed`：已经获得过有效结果，下一场新体验需要 Pro。

### 6.1 开始

用户第一次进入功能时，客户端调用“开始体验”接口。服务端以账号邮箱和功能键为唯一键，原子地创建或返回同一条 `in_progress` 记录，并返回本次页面生命周期使用的访问授权。重复点击、请求重试和多设备同时进入不会创建第二次免费权益。

### 6.2 核销时机

只有出现对用户有实际价值的成功结果后，客户端才调用“核销体验”接口：

- 对话陪练：第一条有效 AI 对话回复成功展示。
- 视频角色扮演：进入角色对话后，第一条有效角色回复成功展示。仅生成场景卡但没有开始对话不核销。
- 实景口语：完成图片理解、出题、用户回答，并成功展示评分结果。
- 拍照 AI：成功展示一张图片的分析结果。

模型超时、网络断开、JSON 解析失败、内容为空、用户在第一条有效结果前取消，均不核销。状态保持 `in_progress`，用户下次进入时复用同一项体验。

### 6.3 核销后的当前会话

核销只阻止开启下一场免费会话，不中断当前已经打开的体验。客户端在当前页面生命周期内保留“开始体验”返回的访问授权，因此对话陪练和角色扮演可以继续正常进行，直到用户主动结束或离开。该授权不用于开启另一场会话，也不跨 App 进程恢复。产品接受正常用户可能进行较长会话，不额外设置固定轮数或倒计时。

### 6.4 进程退出

- 在有效结果出现前退出：服务端仍为 `in_progress`，重启后可重新尝试。
- 在有效结果出现后退出：服务端已经为 `consumed`，重启后开启新会话需要 Pro。
- 本次不要求恢复退出前的对话上下文；恢复的是“不会因为失败白白损失体验”的权益状态，而不是完整会话内容。

## 7. 服务端设计

### 7.1 数据表

在 `whatsub-license/schema.sql` 增加：

```sql
CREATE TABLE IF NOT EXISTS feature_trials (
    email        TEXT   NOT NULL,
    feature_key  TEXT   NOT NULL,
    started_at   BIGINT NOT NULL,
    consumed_at  BIGINT,
    updated_at   BIGINT NOT NULL,
    PRIMARY KEY (email, feature_key)
);
```

无记录等价于 `available`；存在且 `consumed_at IS NULL` 等价于 `in_progress`；`consumed_at IS NOT NULL` 等价于 `consumed`。`feature_key` 只接受服务端白名单中的四个值。

### 7.2 API

新增 `/api/features` 路由，并通过现有 nginx 的 `/api/license/*` 映射供 iOS 使用：

- `GET /api/features/entitlements`
  - 返回当前账号的 Pro 状态及四项体验状态。
- `POST /api/features/:featureKey/start`
  - Pro 用户直接返回 `access: "pro"` 和访问授权。
  - 免费用户无记录时原子创建 `in_progress` 并返回访问授权。
  - 已是 `in_progress` 时幂等返回允许访问及同等范围的访问授权。
  - 已是 `consumed` 时返回 `403 feature_subscription_required`。
- `POST /api/features/:featureKey/consume`
  - Pro 用户幂等成功。
  - 免费用户将现有记录的 `consumed_at` 原子设置为当前时间。
  - 没有先 `start` 的记录返回 `409 feature_trial_not_started`，防止客户端状态机错误。

所有接口使用现有 session bearer，从服务端会话解析单一账号邮箱。客户端传入的邮箱不参与权限判断。

### 7.3 原子性与幂等

- 主键 `(email, feature_key)` 防止并发创建多次体验。
- `start` 使用 upsert 或事务实现，重复请求返回相同状态。
- `consume` 只允许 `consumed_at IS NULL` 的现有记录更新；重复核销返回成功。
- 服务端数据库时间为权威时间，客户端时间不参与权益计算。
- Pro 判断复用现有 `hasActiveSubscription`，同时覆盖 iOS StoreKit 和网页/支付宝订阅。

## 8. iOS 设计

### 8.1 集中权限层

新增单一 `FeatureAccessStore`，负责：

- 拉取并缓存四项权益状态。
- 提供 `start(feature:)` 和 `consume(feature:)`。
- 合并服务端 Pro 状态与 `StoreManager.hasLocalSub` 的购买即时状态。
- 将 `feature_subscription_required` 统一转换为订阅弹窗，而不是让各页面自行解析字符串。

四项页面不得直接读取本地布尔值决定权限，也不得分别实现自己的体验计数。

### 8.2 入口体验

- `available`：入口显示“免费体验 1 次”轻量标记，点击后直接进入，不先弹付费墙。
- `in_progress`：入口显示“继续免费体验”，点击后继续。
- `consumed` 且非 Pro：点击后展示 `SubscribeSheet`。
- Pro：入口保持正常，不显示体验次数。
- 权益状态尚未加载：允许显示页面骨架，但开始 AI 任务前必须完成检查。

### 8.3 订阅页

`SubscribeSheet` 的权益顺序调整为：

1. AI 对话陪练持续使用。
2. 视频角色扮演持续使用。
3. 实景口语与拍照 AI 持续使用。
4. whatSub 托管 AI 月度配额。
5. 50 个云端视频、500 MB / 60 分钟单视频上限。
6. 1000 条个人语料和公共语料库。

价格仍由 StoreKit 商品动态提供，不在新页面硬编码人民币金额。

### 8.4 购买后的即时解锁

用户从付费墙完成 StoreKit 购买后：

1. 沿用现有 JWS 上报与重试流程。
2. `StoreManager.hasLocalSub` 立即解除当前设备的 UI 阻塞。
3. 后台刷新 `/me` 和 `GET /features/entitlements`。
4. 如果服务端登记暂时失败，沿用现有“已扣款但登记失败”的明确错误提示；不得再次要求用户购买。

## 9. 网络与离线行为

- 已缓存为 Pro 的用户离线时沿用当前 App 的离线可用策略，不新增更严格的启动阻塞。
- 免费用户第一次开始某项体验必须联网，因为体验记录必须由服务端原子创建。
- 权益接口失败时显示“暂时无法确认免费体验，请检查网络后重试”，不得误判为已用完，也不得弹出订阅页。
- `consume` 失败时客户端保留待同步标记并重试；服务端仍可能处于 `in_progress`，因此不会提前锁死用户。
- 待同步核销必须持久化到本地并在下次启动重试，不能只存在内存中。客户端在获得有效结果后先落下该标记，再向用户展示结果，尽量缩小“结果已显示但核销尚未记录”的崩溃窗口。
- 托管 LLM 的 token 配额错误与功能权益错误继续分开：前者提示月度额度，后者提示该功能体验已用完。

## 10. 数据与隐私

- `feature_trials` 只保存邮箱、功能键和时间戳，不保存图片、对话文本、API Key 或模型响应。
- BYOK 数据流保持设备直连用户选择的模型服务商。
- 现有 AI 数据发送同意流程继续适用于全部 AI 功能。
- 删除账号时，服务端必须一并删除该邮箱的 `feature_trials` 数据。

## 11. 测试策略

### 11.1 后端

- 每项新账号初始为 `available`。
- `start` 首次创建 `in_progress`，重复调用幂等。
- 同账号同功能并发 `start` 只产生一行。
- 四个功能互不影响。
- `consume` 前必须存在 `start`。
- `consume` 重复调用幂等。
- `consumed` 免费用户再次 `start` 返回 `feature_subscription_required`。
- Pro 用户无论是否存在 trial 行都可 `start`。
- 网页订阅和 iOS 订阅都被识别为 Pro。
- 非白名单功能键被拒绝。
- 账号删除清理体验记录。

### 11.2 iOS 纯逻辑

- `available`、`in_progress`、`consumed`、`pro` 正确映射为入口状态。
- BYOK 和托管 LLM 走同一项功能权限检查。
- 权益网络错误不会映射成订阅墙。
- 第一条有效结果前失败不调用 `consume`。
- 各功能只在规定的成功节点调用一次 `consume`。
- 核销后当前会话不被关闭，下一场会话才触发订阅页。
- 购买成功后本地 Pro 状态立即解锁并触发服务端刷新。

### 11.3 UI 与人工验收

- 四个入口首次均显示“免费体验 1 次”。
- 每项可独立完成一次，不会因为体验了另一项而被锁。
- 托管模式和 BYOK 模式表现一致。
- 模拟超时、断网和模型格式错误不会扣掉体验。
- 完成体验后退出，再次进入显示订阅页。
- 订阅后四项入口全部解锁，旧的 `consumed` 记录不影响 Pro。
- 重装或第二台设备登录同一账号后，已使用状态保持一致。

## 12. 发布与观测

实施分两阶段上线：

1. 先部署向后兼容的服务端表和 API；旧版 iOS 不调用它们，行为不变。
2. 再发布启用四项权限检查的新 iOS 版本。

迁移时不根据历史 AI 使用记录回填 `feature_trials`。新表上线后，所有现有免费账号与新注册免费账号一样，四项功能均从 `available` 开始，各自获得一次完整体验；后续使用状态再按账号跨设备核销。

服务端记录匿名聚合指标：各功能 `start` 数、`consume` 数、体验后付费墙展示数和购买成功数。不得记录 AI 内容。首版不做复杂实验平台，只通过现有日志或简单 SQL 聚合验证转化漏斗。

成功标准：

- 新版本不存在通过 BYOK 持续免费使用四项核心功能的正常产品路径。
- 免费用户仍能无付费完成四项各一次的有效体验。
- 功能权限错误不增加模型调用失败率或误扣体验投诉。
- 订阅页能明确表达 AI 练习价值，而不再主要依赖容量卖点。

## 13. 实施边界

本设计涉及两个仓库：

- `whatsub-license`：数据表、数据库方法、权益 API、鉴权和测试。
- `whatsub-mobile`：集中权限 Store、网络 DTO、四项入口与核销点、订阅页文案和测试。

桌面端本次不增加相同功能门槛。桌面端仍共享同一账号的 Pro 状态和托管 token 配额，但本设计只改变 iOS 四项功能的进入权限。

## 14. 防绕过边界

本设计的目标是消除正式 App 中通过切换 BYOK、重装、换设备或重复请求持续免费使用四项功能的正常路径。由于 BYOK 请求从用户设备直接发送给第三方模型服务商，服务端不可能在不接收用户 API Key 和提示词的前提下对修改版客户端实施绝对 DRM。逆向修改已签名客户端、篡改本地二进制或自行复刻提示词不属于本次威胁模型，也不应为了极少数破解行为牺牲 BYOK 的隐私承诺。
